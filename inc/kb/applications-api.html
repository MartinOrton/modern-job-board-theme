These routes act as a signed-in recruiter (or administrator). See Authentication.

List applications

GET /wp-json/mjb/v2/applications
curl -u "recruiter:xxxx xxxx xxxx xxxx" \
  "https://example.com/wp-json/mjb/v2/applications?job_id=42&status=new&per_page=20"

Each item looks like this:

{
  "id": 88,
  "job_id": 42,
  "job_title": "Senior Web Developer",
  "status": "new",
  "status_label": "New",
  "date": "2026-07-21 14:30:00",
  "cv_access": true,
  "candidate_name": "Alex Example",
  "candidate_email": "alex@example.com",
  "message": "Excited to apply…",
  "resume_url": "https://example.com/?mjb_download=application&mjb_id=88&mjb_nonce=…"
}

When paid CV access is switched on and the recruiter has not unlocked an application, cv_access is false and the candidate's personal details and CV link are left out.

The resume_url is a checked download link: it only works for a signed-in user who is allowed to see that CV.

Update an application

Change an application's stage. The caller must own the job, or be an administrator.

PATCH /wp-json/mjb/v2/applications/{id}
curl -X POST -u "recruiter:xxxx xxxx xxxx xxxx" \
  -H "Content-Type: application/json" \
  -H "X-HTTP-Method-Override: PATCH" \
  -d '{"status":"reviewed"}' \
  "https://example.com/wp-json/mjb/v2/applications/88"

Stages

A stage change fires the application.status_updated webhook and can email the candidate, just like a change in the dashboard.
