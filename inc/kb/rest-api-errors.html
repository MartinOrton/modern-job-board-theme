Errors come back as JSON with a code, a human-readable message, and the HTTP status in data.status:

{
  "code": "mjb_rest_forbidden",
  "message": "Recruiter access required.",
  "data": { "status": 403 }
}

Error codes

WordPress's own errors, such as rest_no_route (the route does not exist, often because the plan does not include the API) can also appear.

Handling errors

  • Treat 401 as "sign in again": check the username and application password.
  • Treat 403 as permanent for that record: retrying will not help.
  • Retry 500 errors and network failures a few times with an increasing wait.
