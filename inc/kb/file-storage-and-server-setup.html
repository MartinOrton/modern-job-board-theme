Where files are stored

User files are kept under wp-content/, not in the plugin folder (an update would delete them) and not in the Media Library (files there are public).

Both folders are created when the plugin is activated, with resumes/, logos/ and photos/ inside, sorted by year and month. WordPress must be able to write to them; the usual folder permission is 755.

Block direct access to [mjb_doc plural lower]

[mjb_doc plural] are only ever sent through a download link that checks who is asking. A direct request for a file in wp-content/mjb-private/ must fail.

Apache and LiteSpeed

The plugin writes a .htaccess file into wp-content/mjb-private/ that denies all access. This works on most hosts, including shared cPanel hosting, with no extra set-up.

IIS

The plugin writes a web.config file that denies all users. Make sure no parent web.config overrides it.

nginx

nginx ignores .htaccess files, so add this rule inside your site's server { } block (adjust the path if WordPress is in a sub-folder):

# Modern Job Board: CVs are never served directly
location ~* /wp-content/mjb-private/ {
    deny all;
    return 403;
}

Then test the configuration and reload nginx:

sudo nginx -t && sudo systemctl reload nginx

On managed hosts where you cannot edit nginx yourself, ask your host's support to add the rule.

Older versions stored files in wp-content/plugins/modern-job-board/mjb-private/ or wp-content/uploads/mjb-private/. They are still read from there if present, so keep a deny rule for those paths too until you are sure they are empty.

Check that it works

Open https://your-site.com/wp-content/mjb-private/ in a browser. You must get 403 Forbidden. Then sign in as a recruiter and download a [mjb_doc lower] from an application: that must work.

Cloudflare and other CDNs

Never let a CDN cache anything under wp-content/mjb-private/. If you use a "cache everything" rule, exclude that path. Logos and photos in mjb-brand can be cached safely.
