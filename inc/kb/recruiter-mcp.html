The AI assistant for recruiters lets a recruiter run their hiring by chatting with ChatGPT, Claude, Gemini or another AI assistant. They can ask it things like “Which of my jobs have new applications?” or “Move everyone still New after 14 days to Reviewed”, and the assistant lists and updates their jobs, reviews applications and edits their company on the board, within the same limits as the recruiter dashboard.

MCP stands for Model Context Protocol, the open standard AI assistants use to work with other systems. The first section below is all a recruiter needs; the rest is the technical reference.

POST /wp-json/mjb/v1/mcp

The route speaks JSON-RPC 2.0 with the methods initialize, tools/list and tools/call. It is only registered on plans that include the REST API.

Who can use it

Every call must come from a signed-in user with the recruiter (employer) role. Candidates, visitors and administrators who are not recruiters are refused. Results are limited to that recruiter's own jobs, the applications to those jobs, and their company. There is no tool for candidate logins or for checkout.

Which AI assistants can connect

Any AI assistant that can add a custom MCP connector. There are two ways to connect, and both give the assistant the same tools.

  • One-click sign-in, for ChatGPT, Claude and other assistants that support OAuth. The recruiter connects it themselves in about a minute. Custom connectors are only available on some ChatGPT and Claude plans.
  • An application password, for developer tools such as Claude Code and Gemini CLI that can send a fixed Authorization header. Usually set up by whoever looks after the website.

Connect with one-click sign-in

  1. In the recruiter dashboard, open AI assistant and copy the server address.
  2. In ChatGPT or Claude, add a custom connector and paste the address as the server URL. Leave any client ID and secret fields empty.
  3. The board's sign-in page opens. Sign in as the recruiter, check what the assistant will and will not be able to do, and choose Allow.

The assistant never sees the recruiter's password. It gets a token that only works for that recruiter's MCP tools. Every connected assistant is listed under AI assistant in the dashboard, where the recruiter can disconnect it at any time. Changing the account's password, or removing its recruiter role, disconnects all of them.

For developers: the sign-in is OAuth 2.1 with PKCE (S256) and dynamic client registration. Clients discover it from the WWW-Authenticate header on a 401 response, or from /.well-known/oauth-protected-resource and /.well-known/oauth-authorization-server. The scope is mjb:recruiter. Access tokens last an hour; refresh tokens last 30 days and are replaced each time they are used. The board must be served over HTTPS.

Connect with an application password

Create an application password for the recruiter's account. The header value is Basic followed by the recruiter's user name and application password, joined by a colon and Base64-encoded:

printf '%s' "RECRUITER:APPLICATION_PASSWORD" | base64

Claude Code:

claude mcp add --transport http job-board \
  https://example.com/wp-json/mjb/v1/mcp \
  --header "Authorization: Basic BASE64_CREDENTIALS"

Gemini CLI, in settings.json:

{
  "mcpServers": {
    "job-board": {
      "httpUrl": "https://example.com/wp-json/mjb/v1/mcp",
      "headers": { "Authorization": "Basic BASE64_CREDENTIALS" }
    }
  }
}

One-click sign-in needs Modern Job Board 0.9.0-beta.178 or later. The application-password route needs 0.9.0-beta.177 or later: earlier versions sent two tool schemas in a form that standard MCP clients reject, so the assistant found no tools.

Example

curl -u "RECRUITER:APPLICATION_PASSWORD" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"list_my_jobs","arguments":{}}}' \
  "https://example.com/wp-json/mjb/v1/mcp"

Tools

Start a new assistant connection with list_my_jobs and get_recruitment_funnel_summary: they give it the context for most follow-up questions.
