Application passwords

For scripts and other systems, use a WordPress application password over HTTPS. It works like a separate password for one connection, and can be revoked at any time without changing the user's own password.

  1. Sign in to wp-admin as the user the connection will act as, or edit that user as an administrator.
  2. Open Users → Profile and scroll to Application Passwords.
  3. Enter a name, such as "ATS connection", and select Add New Application Password.
  4. Copy the password shown. It is only shown once.

Send it with HTTP Basic authentication:

curl -u "USERNAME:APPLICATION_PASSWORD" \
  "https://example.com/wp-json/mjb/v2/applications?per_page=20"

Only use application passwords over HTTPS. Keep them out of code you share, and give each system its own password so you can revoke one without affecting the others.

Browser code on the same site can also use WordPress's normal cookie authentication with a REST nonce, and other REST authentication plugins work too.

What each user can see

  • Recruiters only see their own data. A recruiter only sees applications to jobs they posted. A recruiter with no jobs gets an empty list, never everyone's applications.
  • Administrators can list all applications on v2.
  • Candidates only ever see their own profile.
  • The AI assistant for recruiters (MCP) does not give administrators that wider access: every MCP call is limited to the signed-in recruiter's own records.
